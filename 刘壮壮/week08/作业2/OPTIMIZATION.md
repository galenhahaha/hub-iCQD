# 后续优化

第一版目标是跑通研究循环并交出四类产物。下面是已发现、但尚未做成产品能力的点。规格仍以 `README.md` 为准；改代码时的短原则见 `CLAUDE.md`。

整体目标：**报告尽量准确、可追溯**。时效和来源品质是证据好不好的评分项，不是检索开关。

## 案例：`55bc859784c9`

主题「目前市面上所有 AI coding 编程工具对比」，漏了 Codex。

- 主因是**查询策略**：21 个检索词没有任何一条点名 Codex；规划被中文 SEO 横评带成 Cursor / Windsurf / Copilot。
- 放大因素是**来源品质**：Bocha 中文查询大量回到 CSDN / 掘金 / 博客园；snippet 里的 Codex 多半是 2021 年 Copilot 底层模型，或 Azure 模型名。
- 不是「窗口不够新」。同一套 Bocha，改成 `OpenAI Codex CLI` / `Codex vs Cursor vs Claude Code` 能搜到当前产品。

结论：先改「搜什么、信什么」，不要再加年份硬规则。

## 待办

### 1. 查询策略（优先）

- 规划输出检索意图，不要写死年份。竞品 / 市面盘点要**点名当前仍在更新的产品**，并可用中英查询。
- 评审补检对着缺口：缺某产品就点名搜，缺定价就搜官方页；不要把缺口说明整句拿去搜，也不要再堆同类横评。
- 排序可以让新材料权重大一些，空结果再放开；**不要**主题级写死 `freshness=oneYear`，也不要强制把关键词里的去年改成今年。

回退已写入引擎的硬逻辑（`_wants_latest`、`_ensure_current_year`、默认 `oneYear`、命中少再改年份）：改成弱偏好或交给规划 / 评审，而不是控制流里的总开关。

### 2. 置信度按证据打分

现在 `_confidence` 大致是：来源 ≥8 且 ≥2 轮且没有「模型推断」→ high，≥4 → medium。条数被当成质量。

应改成多维评估（主题吃时效时才加重时间）：

- 能否追溯到 URL；无来源必须标「模型推断」
- 来源类型：官方 / 一手 vs 自媒体聚合
- 是否独立交叉验证（同文换域名不算多源）
- 发布日期是否与主题匹配；过时材料可以写进报告，但要标明时间并降低档位
- `as_of` 只表示评估截止日，不是「材料必须出生在这一天」

### 3. 单一取证通道

当前只有 Bocha 网页搜索，且只读标题 / 摘要 / snippet。

- 只有这一种通道时，即使来源很多，也不该轻易标 high。
- 若要提高上限，再考虑第二通道（官方文档、指定 URL），那是另一次改动，不是把现有搜索窗口收得更死。

### 4. 抽取与综合

- 冲突事实按来源日期和站点品质取舍，而不是谁先出现在草稿里。
- 避免把旧模型名当成当前独立产品（案例里的 Codex）。
- 综合阶段来源过多时，不要把官方 / 较新材料淹没在 100+ 条 snippet 里。
