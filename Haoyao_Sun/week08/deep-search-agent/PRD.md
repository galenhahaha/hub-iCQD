# 深度研究助手 - 产品需求文档 (PRD)

## 1. 产品概述

**产品名称**：深度研究助手 (Deep Research Assistant)

**产品定位**：基于大语言模型 + 检索增强的自动化深度研究工具，帮助用户快速完成主题研究并产出结构化报告。

**核心价值**：自动化多轮检索与信息整合，减少人工搜索时间，生成具备来源追溯的研究报告。

---

## 2. 功能需求

### 2.1 输入

| 字段 | 类型 | 说明 |
|------|------|------|
| 研究主题 | 文本 | 用户输入的研究主题/问题 |
| 最大迭代轮次 | 整数 | 默认 3 轮，上限 5 轮 |

### 2.2 输出

#### 2.2.1 结构化研究报告

包含以下四个部分：

1. **摘要** (Abstract)
   - 研究主题概述
   - 关键发现摘要 (3-5 条)
   - 主要结论一句话

2. **正文** (Body)
   - 按主题拆分的章节结构
   - 每个论点附来源支撑
   - 数据、案例、对比分析

3. **结论** (Conclusion)
   - 研究主要发现
   - 实践建议
   - 局限性说明

4. **未决问题** (Unresolved Questions)
   - 当前无法确定的问题
   - 待进一步研究的领域

#### 2.2.2 来源列表

- 格式：`[序号] 标题 - URL`
- 每条检索结果包含：`title`、`url`、`snippet`

#### 2.2.3 研究过程日志

记录每轮迭代：
- 时间戳
- 轮次编号
- 执行的检索词
- 检索到的结果数量
- 本轮发现摘要
- 子问题列表（待检索项）

#### 2.2.4 置信度说明

- 每项关键结论标注置信度等级（高/中/低）
- 说明依据：来源权威性、信息一致性、证据充分性

## 3. 核心流程

```
┌─────────────────────────────────────────────────────────────┐
│                      用户输入                               │
│            (研究主题 + 最大迭代轮次)                         │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│  阶段1：规划 (Planning)                                      │
│  - LLM 分析研究主题                                          │
│  - 拆解为 3-7 个子问题/研究方向                              │
│  - 制定检索策略                                              │
└────────────────────────────┬────────────────────────────────┘
                             │
              ┌──────────────┴──────────────┐
              │     迭代循环 (N 轮)          │
              ▼                              ▼
┌─────────────────────────────┐  ┌──────────────────────────────┐
│ 阶段2：检索 (Retrieval)      │  │ 阶段3：阅读 (Reading)        │
│ - 对子问题进行检索            │  - 抓取关键页面内容            │
│ - 调用博查 Web Search API   │  - 抽取关键信息                │
│ - 获取标题+摘要+URL          │  - 提取事实/数据/观点          │
└─────────────────────────────┘  └──────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ 阶段4：判断 (Judgment)                                      │
│ - 已覆盖主题的关键方面？                                     │
│ - 新发现的子问题是否需要补检？                               │
│ - 是否达到迭代终止条件？                                     │
│         是 ──▶ 终止 / 否 ──▶ 继续下一轮                     │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ 阶段5：综合 (Synthesis)                                     │
│ - 整合所有检索结果与阅读笔记                                 │
│ - 生成结构化报告                                             │
│ - 生成来源列表                                               │
│ - 生成置信度说明                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 迭代终止条件

满足以下任一条件即终止：
1. 达到最大迭代轮次
2. 所有子问题已检索完毕
3. 新检索结果与已有信息高度重复
4. 连续两轮无新发现

## 4. 技术实现

### 4.1 搜索 API

**接口**：博查 Web Search API

- **URL**：`POST https://api.bocha.cn/v1/web-search`
- **Header**：`Authorization: Bearer sk-3d2293ad83aa4823a7c7ce8dd5ff8c72`
- **Content-Type**：`application/json`
- **请求体**：
  ```json
  {
    "query": "检索关键词",
    "count": 10,
    "page": 1
  }
  ```
- **响应字段**：`title`, `url`, `snippet`

### 4.2 主要模块

| 模块 | 职责 |
|------|------|
| `app.py` | Streamlit 主界面 |
| `researcher.py` | 研究流程控制器 |
| `searcher.py` | 博查 API 封装 |
| `llm_client.py` | OpenAI API 调用 |
| `report_generator.py` | 报告生成器 |

---

## 5. 非功能需求

- **响应时间**：单轮检索 < 10 秒
- **稳定性**：API 超时重试 3 次
- **用户体验**：实时显示研究进度 (日志流)
- **保密性**：用户输入不持久化存储

---

## 6. 验收标准

1. ✅ 输入研究主题和迭代轮次后，点击开始能正常运行
2. ✅ 每一轮迭代都会显示检索结果和研究日志
3. ✅ 最终输出包含：摘要、正文、结论、未决问题
4. ✅ 来源列表包含 URL 和标题，可点击
5. ✅ 研究过程日志清晰展示各轮次状态
6. ✅ 置信度说明标注在关键结论处
7. ✅ 界面响应流畅，出错时友好提示
