# Claude Code 练习约定

## 目标

这是一个 AI Coding 实践工作区。`README.md` 是需求的唯一来源。本项目用于练习需求分析、任务拆解、实现、测试和复盘，不提供原综合案例的参考实现。

## 协作方式

1. 开始编码前，先阅读 `README.md`，用自己的话复述目标、非目标和验收标准。
2. 先给出简短的实现计划与预计修改的文件，等待用户确认后再编码。
3. 小步实现：先完成最小可运行版本，再补异常处理和测试。
4. 每完成一个阶段都运行相关测试，不得仅凭代码阅读声称完成。
5. 遇到需求歧义时先提出问题，不自行扩大功能范围。
6. 解释关键决策，尤其是 Workflow 控制、Agent 式判断、依赖注入和循环停止条件。

## 技术边界

- 使用 Python、FastAPI、Pydantic 和 pytest。
- 默认使用可预测的本地模拟搜索；设置 `RESEARCH_MODE=real` 后默认接入无需 API Key 的 DuckDuckGo 和 OpenAI 兼容 LLM，也可选用 Bocha，测试仍必须保持离线可运行。
- 最多两轮研究循环。
- 不实现前端、数据库、用户系统、部署系统、MCP 或多 Agent SDK，除非用户明确追加需求。
- 不在代码、日志或提交记录中存放密钥。
- 真实模式的密钥只从 `.env` 或环境变量读取；不得打印密钥、完整授权请求或敏感响应。

## 质量要求

- 保持模块职责清晰，避免为了展示模式而过度设计。
- 外部服务通过抽象接口或依赖注入隔离，方便测试和替换。
- 为正常路径、输入校验、URL 去重、轮数上限和搜索失败编写测试。
- 最终交付时列出实际运行过的验证命令及结果，并给出一段简短复盘。
