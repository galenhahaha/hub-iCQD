## 1. 目标与范围

输入一个研究主题，自动完成「规划 → 多轮检索 → 阅读抽取 → 判断是否补检 → 综合」，产出四类成果物，端到端可运行。

四类成果物（硬要求，一条不可丢）：

1. **结构化研究报告**：摘要、分节正文、关键结论、遗留问题。
2. **来源列表**：每条结论关联 URL / 标题 / 来源，可追溯。
3. **研究过程记录**：检索关键词、已读页面、迭代轮数。
4. **置信度说明**：可靠程度、信息截止时间、无来源结论标「模型推断」。

三个产品硬要求：

1. **迭代是特性**——保留「判断是否补检」这一环，不能一次检索就出报告。
2. **可追溯是硬要求**——每条结论关联来源 URL/标题，来源随报告产出。
3. **过程记录要落盘**——检索关键词、已读页面、迭代轮数都要记录。

## 2. 技术栈（锁定）

- 后端：FastAPI + uvicorn；Pydantic v2 做数据模型。
- Agent 框架：`openai-agents` SDK，`Runner.run`（async）。
- LLM：DeepSeek `deepseek-v4-flash`，OpenAI 兼容接口 `https://api.deepseek.com/`。
- 搜索：Bocha 网页搜索 `POST https://api.bocha.cn/v1/web-search`（`Authorization: Bearer <key>`，body `query`/`summary`/`count`）。
- 提示词：Jinja2 模板，与代码分离（`backend/templates/`）。
- 配置：只读取进程环境变量，不加载 `.env`；HTTP 客户端用 `httpx`。

## 3. 架构

### 3.1 角色划分

**角色 agent（无工具、单次 LLM 调用）**，提示词各一模板：

| 角色 | 职责 | 输入 → 输出 |
|------|------|-------------|
| `keyword` | 拆解子问题为搜索关键词 | topic → `list[str]`（3–5 个） |
| `summary` | 把某关键词的检索结果总结成一段正文 | topic + keyword + results → 一段纯文本（500–900 字，无 URL） |
| `judge` | 判断是否补检 + 生成新关键词 | topic + draft + sources + searched → `JudgeDecision` |
| `report` | 输出报告元信息 + 渲染 HTML | topic + draft + sources + confidence → `(ReportContent, html)`（两次 LLM 调用） |

**研究引擎（编排器）** `DeepResearch`：确定性控制流、不调 LLM，把角色串成流水线，逐关键词检索、累积 `draft` 与 `sources`、每轮通过 `on_progress` 回调把中间结果写盘。

### 3.2 对外接口

- `POST /api/research`：body `{"topic": "..."}` → `202` + `{"research_id", "status": "pending"}`，随后 `asyncio.create_task` 后台执行。
- `GET /api/research/{id}`：轮询，返回 `ResearchRecord`（status ∈ `pending/running/completed/failed` + 四类成果物）。
- `GET /api/research`：列表。
- `GET /health`：健康检查。

## 4. 数据模型（`models.py`，Pydantic v2，字段名对齐参考实现）

- `Status(str, Enum)`：`pending / running / completed / failed`
- `ResearchRequest`：`topic: str`（min_length=1，max_length=500）
- `SourceRef`：`url: str`、`title: str = ""`
- `JudgeDecision`：`sufficient: bool = False`、`reason: str = ""`、`new_keywords: list[str] = []`
- `KeywordOutput`：`keywords: list[str]`
- `DraftBlock`：`round: int`、`keyword: str`、`text: str`
- `ProcessStep`：`type: str`（plan/search/summarize/judge）、`round: int = 0`、`detail: dict = {}`
- `Conclusion`：`text: str`、`sources: list[SourceRef] = []`、`is_model_inference: bool = False`
- `Section`：`heading: str`、`body: str`、`conclusions: list[Conclusion] = []`
- `ConfidenceNote`：`overall: str = "medium"`（high/medium/low）、`info_cutoff: str = ""`、`notes: list[str] = []`
- `ReportContent`：`title`、`summary`、`sections: list[Section]`、`key_conclusions: list[Conclusion]`、`open_questions: list[str] = []`
- `ReportOutline`：`title`、`summary`、`key_conclusions: list[Conclusion] = []`、`open_questions: list[str] = []`（report 第一次调用产物，无 sections）
- `Source`：`url`、`title: str = ""`、`site_name: str = ""`、`snippet: str = ""`、`accessed_at: str = ""`
- `ResearchProcess`：`plan: list[str]`、`search_queries: list[str]`、`reviewed_urls: list[str]`、`iterations: int = 0`、`steps: list[ProcessStep] = []`
- `ResearchRecord`（GET 响应 / 落盘对象）：`research_id`、`topic`、`status`、`created_at`、`updated_at`、`error: str | None`、`report: ReportContent | None`、`report_html: str`、`sources: list[Source]`、`draft: list[DraftBlock]`、`process: ResearchProcess | None`、`confidence: ConfidenceNote | None`
- `DeepResearchResult`：`report`、`report_html`、`sources`、`draft`、`process`、`confidence`

## 5. 研究循环（编排器 `DeepResearch.run`）

1. **规划**：`KeywordAgent.generate_keywords(topic)` → 初始关键词（空则回退 `[topic]`）；记录 `process.plan` + `ProcessStep("plan")`；触发 `on_progress`。
2. **循环**（`round_no < max_rounds`）：对每个未检索的关键词 →
   - `tools.web_search(kw)`（单次失败→空列表，不致命）→ 按 URL 去重累积进 `sources` 与 `process.reviewed_urls`，记 `search` step；
   - `SummaryAgent.summarize(...)` → 一段正文追加为 `DraftBlock(round, keyword, text)`，记 `summarize` step；
   - `JudgeAgent.judge(...)` → 记 `judge` step → 触发 `on_progress`；
   - 若 `sufficient` 或 `round_no >= max_rounds` 或无新关键词则跳出；否则用 `new_keywords` 继续（跳过已检索）。
3. **综合**：
   - `_compute_confidence`（确定性）：来源数 ≥12→high，≥5→medium，否则 low；`info_cutoff` = 最新来源日期（缺省今天）；notes 文本。
   - `ReportAgent.generate(...)` → `(report, report_html)`。

`on_progress` 快照：`{"process": {...}, "draft": [{round, keyword, text}], "sources": [{url, title, ...}]}`；回调兼容 sync/async（`inspect.isawaitable` 判断）。

## 6. 循环参数（环境变量可配，默认值）

| 变量 | 含义 | 默认 |
|------|------|------|
| `RESEARCH_MAX_ROUNDS` | 检索/补检轮数上限 | 3 |
| `BOCHA_SEARCH_COUNT` | 每次检索返回结果数 | 10 |
| `LLM_RETRIES` | 空输出重试次数 | 3 |
| 关键词数 | keyword 生成 | 3–5 |
| 摘要长度 | summary 输出 | 500–900 字 |

## 7. 前端（极简内置）

FastAPI 托管单页 `backend/static/index.html`：输入话题 → 轮询 `GET /api/research/{id}` → 展示四类成果（报告 / 来源 / 过程 / 置信度）。纯静态 HTML+JS，无 Node 构建；界面中文。

## 10. 必须实现的坑（参考实现踩过）

1. **空输出重试**：DeepSeek 偶发 200 + 空 `message.content`；`BaseAgent._run` 重试 `LLM_RETRIES` 次、每次退避 1s。
2. **不支持 `output_type`**：不能给 `Agent(output_type=...)`；用提示词强制单 JSON + `parse_json` 兜底（先 `model_validate_json`，失败再 ` ```json ` 围栏正则）。
3. **提示词与代码分离**：所有提示词进模板，`BaseAgent._render` 用 Jinja2。
4. **中间结果落盘**：每轮 `on_progress` 写 process/draft/sources，状态仍 `running`；异常时保留已写中间结果。
5. **角色 agent 无工具** + `max_rounds` 有界 → 防自循环、保证收敛。
6. **report 两次调用**：先 `ReportOutline`（标题/摘要/结论/遗留问题），正文分节直接映射 draft 段落（heading=关键词，不 LLM 重组）；再渲染 `ReportContent` 为自包含 HTML（`final_output` 返回原始 HTML，不包 JSON，避免转义错误）。
7. **async 只用 `Runner.run`**，不用 `run_sync`；模块级 `set_default_openai_api("chat_completions")` + `set_tracing_disabled(True)`。
8. **搜索工具**：`web_search` 是普通 async 函数返回 `list[dict]`（title/url/snippet/site_name/date，snippet 截断 500 字）；无 `fetch_page`，摘要基于搜索摘要而非整页。

## 11. 落盘与状态机

- JSON 文件 `backend/data/research/{id}.json`，整文件覆盖写，`threading.Lock` 保护。
- 状态机 `pending → running → completed/failed`。
- 启动时 `ensure_data_dir()`；`logging.basicConfig(level=INFO)`。
